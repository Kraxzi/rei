# REI — Архитектура

Версия 1.0 · 24.11.2026 · исходное ТЗ: REI_Master_Spec_v3 (проект «батя»), отклонения — `docs/Decisions.md`.

## 1. Главные ограничения

1. **Всё бесплатно.** Cloudflare Workers Free на аккаунте бати + Gemini free tier. Платный компонент допускается только по явному решению владельца.
2. **Один пользователь сейчас, много — потом.** Все таблицы с пользовательскими данными имеют `user_id`; роли и тарифы — этап 8.
3. **Никаких серых источников.** Крупные порталы не используются. Только аукционы, госимущество, банки, сайты/фиды агентств после аудита и ручного одобрения.
4. **Цифры считает код.** ИИ только объясняет и извлекает данные из текста; любые числа в отчётах — из детерминированного финансового движка.

### Лимиты Cloudflare Free (проверено 24.11.2026, общие для всего аккаунта — делим с ботом LIGURIA LIFE)

| Ресурс | Лимит | Что это значит для нас |
|---|---|---|
| Запросы Workers | 100 000 / сутки | для одного пользователя с запасом |
| CPU на вызов | 10 мс | тяжёлую работу дробим на сообщения очереди; HTML разбираем потоково (HTMLRewriter) |
| Subrequests на вызов | 50 | один вызов обрабатывает ≤ ~40 страниц, остальное — через очередь |
| Cron Triggers | 5 на аккаунт | REI использует 1–2 расписания, внутри — диспетчер |
| Queues | 10 000 операций / сутки, хранение 24 ч | бюджет сканирования; считаем операции |
| D1 | 5 млн чтений / 100 тыс. записей в сутки, 5 ГБ, 10 БД | записи — узкое место, пишем только изменения |

## 2. Стек (замена стека из ТЗ)

| ТЗ | REI сейчас | Почему |
|---|---|---|
| Python + FastAPI | TypeScript, Cloudflare Worker + Hono | бесплатный хостинг, один язык с фронтом |
| PostgreSQL + PostGIS | Cloudflare D1 (SQLite) + гео в коде | бесплатно; объёмы маленькие, bbox-индекс + точная проверка в коде |
| Redis + Celery | Cron Triggers + Queues | бесплатно, встроено |
| Playwright | не используется | только `fetch` разрешённых страниц; браузер нужен лишь для обхода защит, а это запрещено |
| S3 | не используется | фото — ссылками на оригинал (R2 требует привязки карты) |
| OpenAI через AI Provider Layer | Gemini через тот же слой | ключ уже есть, бесплатный тариф; провайдер заменяем |
| OCR | Gemini (vision) | фото табличек «Vendesi», сканы документов |
| React + Next.js | React + Vite (PWA), статика из того же Worker | Next.js на Workers избыточен; PWA ставится на Android |
| Telegram Bot | Web Push в PWA; Telegram — опционально позже | основной клиент — приложение |
| Sentry / Prometheus / Grafana | Workers Logs + таблицы `scan_runs` / `source_health` + страница статуса | бесплатно |
| Docker | `wrangler dev` локально, GitHub Actions → Cloudflare | нет серверов |

## 3. Структура репозитория (модульный монолит)

```
rei/
  packages/
    core/            # чистая бизнес-логика, без Cloudflare. 100% покрытие тестами важных формул
      src/taxonomy/      категории, типы, схемы полей
      src/geo/           расстояния, bbox, полигоны, geohash
      src/financial/     формулы, модели категорий, сценарии, FX
      src/scoring/       Investment Score, профили весов, уверенность
      src/dedup/         нормализация адресов, fuzzy, вероятность совпадения
      src/monitoring/    сравнение снимков объявлений → события
  apps/
    api/             # Cloudflare Worker: HTTP API + cron + queue consumers + статика PWA
      src/routes/        HTTP-эндпоинты (тонкие, вызывают core и repositories)
      src/repositories/  SQL к D1
      src/connectors/    адаптеры источников (единый интерфейс)
      src/jobs/          cron-диспетчер, обработчики очередей
      src/ai/            AI Provider Layer (Gemini), бюджет, кэш
      src/notifications/ Web Push
      migrations/        SQL-миграции D1
    web/             # PWA (React + Vite + TypeScript)
  docs/
  .github/workflows/ # CI: тесты; деплой в Cloudflare
```

Правило: бизнес-логика живёт только в `packages/core`. `apps/api` — ввод/вывод (HTTP, БД, сеть, ИИ). `apps/web` — интерфейс. Одна и та же формула нигде не дублируется.

## 4. Потоки данных

### 4.1 Сбор (каждые N часов)

```
cron → dispatcher: какие источники пора сканировать (по расписанию и приоритету)
     → queue "scan": одно сообщение = одна страница/пачка источника
     → connector.fetchPage() → raw payload (сохраняем как есть) → connector.normalize()
     → Уровень 1: программные фильтры (подходит ли хоть под один активный профиль)
     → dedup: кандидаты по geohash/цене/площади → вероятность → merge / manual review
     → monitoring: сравнение с прошлым снимком → события (новое, цена ↓/↑, снято, вернулось…)
     → queue "analyze": финансы + score (код), затем Уровень 2/3 ИИ для прошедших отбор
     → notifications: по порогам пользователя, без дублей (ключ события)
```

Идемпотентность: каждое сообщение очереди несёт `job_key`; обработанные ключи пишутся в `job_runs`, повтор — no-op. Ошибки → `scan_runs` со статусом и текстом, источник с серией ошибок → `source_health.status = degraded`.

### 4.2 Ручной ввод
- «Поделиться» ссылкой (Web Share Target) → только домены одобренных источников (агентства, аукционы). Порталы отклоняются с объяснением.
- Фото таблички → Gemini vision → черновик объекта → подтверждение пользователем.
- Импорт CSV/JSON (ТЗ, этап 2) — для тестов и ручных выгрузок; тестовые данные помечаются `is_test = 1` и не смешиваются с реальными в аналитике.

### 4.3 Поиск агентств (автоматическое обнаружение источников)
```
пользователь добавляет регион → Overpass (OSM: office=estate_agent / shop=estate_agent с website)
  → кандидаты в sources (status = candidate)
  → аудит: robots.txt, антибот/капча (→ сразу rejected), отпечаток CRM, sitemap, JSON-LD, пробный сбор
  → карточка «на одобрение» с выжимкой правил сайта (Gemini) → человек жмёт «подключить» → status = approved_public
```

## 5. Источники: интерфейс коннектора

```ts
interface SourceConnector {
  id: string;                       // 'pvp-it', 'crm-getrix', 'jsonld-generic', ...
  accessStatus: AccessStatus;       // из ТЗ 5.1
  listPages(ctx): AsyncIterable<PageRef>;      // что сканировать (sitemap, пагинация, API)
  fetchPage(ref, ctx): Promise<RawPayload>;    // один subrequest, уважает rate limit источника
  normalize(raw, ctx): NormalizedListing[];    // в общую модель + provenance по полям
}
```
Статусы доступа (ТЗ 5.1): `official_api`, `partner_feed`, `authorized_account`, `approved_public`, `manual_import`, `not_connected`, `forbidden`. Коннектор без статуса из первых пяти не запускается.

Rate limit: по умолчанию ≤ 1 запрос / 5 с на домен, User-Agent с контактом, уважение `robots.txt` и `Crawl-delay`.

## 6. Финансовый движок

- Чистые функции в `packages/core/src/financial`. Деньги — в центах (целые числа), ставки — доли (0.05 = 5%).
- Общие формулы: полная стоимость приобретения, GRI, NOI, gross/net yield, cap rate, cash-on-cash, денежные потоки по годам, IRR (Ньютон + бисекция), NPV, окупаемость, общая доходность с учётом продажи, аннуитет кредита.
- Модели категорий: `residential_long_term`, `residential_short_term`, `commercial_lease` (rent roll, WAULT, вакантность), `parking` (места × ставка × загрузка), `hospitality` (ADR × occupancy = RevPAR, персонал, комиссии платформ), `land` (аренда/агродоход, без «потенциала застройки» в цифрах без подтверждения), `industrial` (полезная площадь × ставка), `storage`. Каждая категория таксономии указывает `financial_model`.
- Сценарии: пессимистичный / базовый / оптимистичный × горизонт 1/3/5 лет. Каждый результат возвращает список предположений с источником.
- Налоги покупки по странам берутся из `country_rules` (с источником и датой проверки); если правило не проверено — результат помечается `confidence: low`.

## 7. AI Provider Layer

```ts
interface AIProvider { generate(req: AIRequest): Promise<AIResult> }   // Gemini сейчас, OpenAI/Claude позже
```
- Уровень 1 — код (фильтры). Уровень 2 — дешёвая модель (Flash-Lite): классификация, извлечение полей, проверка полноты. Уровень 3 — Flash/Pro: глубокий анализ только топ-объектов.
- Кэш по хэшу (промпт-версия + входные данные) в `ai_analyses`; повторный анализ только при изменении данных.
- Дневной бюджет вызовов в KV; при исчерпании — анализ откладывается, приложение работает без ИИ.
- Каждый анализ хранит: вывод, использованные данные, источники, дату, недостающие сведения, предположения, уверенность, риски, что проверить (ТЗ XII). Числа в тексте ИИ подставляются из расчёта, а не генерируются.

## 8. Авторизация и безопасность

- **Passkeys (WebAuthn)**: вход отпечатком пальца на Android. Фишингоустойчиво, это и есть MFA для администратора; паролей не храним вовсе. Первый пользователь регистрируется по одноразовому коду приглашения (секрет `BOOTSTRAP_CODE`).
- Сессия: HttpOnly Secure cookie, id сессии в D1, срок + продление, отзыв.
- Секреты только в Cloudflare secrets / GitHub secrets. Чувствительные поля (токены аккаунтов источников, если появятся) — AES-GCM с ключом из секрета.
- Audit log на все изменяющие операции. Rate limit на API (KV-счётчики). HTTPS — по умолчанию у Cloudflare.
- Бэкап: ежедневный экспорт D1 (`wrangler d1 export`) из GitHub Actions в артефакт; плюс D1 Time Travel (точка восстановления за 7 дней на free — проверить).
- GDPR: персональные данные — только самого пользователя и контакты агентств из открытых источников; экспорт и удаление своих данных по запросу.

## 9. Клиент (PWA)

React + Vite + TypeScript, MapLibre + OpenFreeMap. Манифест + service worker: установка на рабочий стол, офлайн-оболочка, Web Push, Web Share Target. Адаптивный: телефон в приоритете (батя — только телефон), планшет и десктоп тоже.
